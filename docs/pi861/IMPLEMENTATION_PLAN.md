# Pi861 首版开发计划

## 1. 产品边界

本项目是用户自研 Agent 平台，不通过 Codex、Claude Code 等外部 Agent 产品执行任务。
复用 Pi 的模型适配、工具循环、会话和扩展接口；新增统一的路由、调度、权限、恢复与记忆协议。
社区项目作为实现参考。不得将多个独立编排器叠加管理同一任务。

## 2. 已确认需求及验收条件

### R1 多模型执行策略
- 每个 Agent 拥有多个具备明确能力、数据范围和配置身份的模型配置。
- 入口一次选择执行模式与初始模型：直接完成、固定模型、动态模型。
- 固定模式不反复路由，但保留异常升级通道。动态路由在阶段、需求、证据变化时触发。
- 复杂工作优先质量；不可仅按价格决定能力。所有子 Agent 受相同策略及全局预算约束。
- 验收：能力不足、未授权、上下文容量不够的配置不会被选择；固定模式的正常回合不切换；异常可以升级。

### R2 模型故障接管与恢复回切
- 分离 preferred（当前首选）与 active（实际执行）配置；故障不改变首选。
- 自动使用备用与自动回切是两个独立开关。运行中修改不重做已经完成的操作。
- 有限重试、分类错误、超时、熔断、轻量恢复探测及安全边界回切。
- 用户取消不触发接管；迟到旧响应没有执行权；未知副作用先核对，不盲目重试。
- 验收：四种开关组合、故障期间更换首选、连续探测、旧响应、取消和无合格备用。

### R3 持续多 Agent / 多模块 / 多节点
- 目标、计划、任务、执行尝试与验收结果分开建模。
- 事件驱动的就绪队列持续补位，不等待整批最慢任务。
- 前置依赖、写入范围、节点能力、租约及尝试编号约束执行。
- 计划可滚动更新，不为所有后台项目写死同一工作流。
- 小组持续存在，执行器可替换；所有后代计入全局资源限制。
- 验收：A 完成后依赖 A 的 C 在无关 B 完成前可以运行；节点租约失效后的旧结果拒绝；依赖环拒绝；有冲突的写入不并行。
- 多节点运输、沙箱、分支/worktree 和集成门禁必须有真实实现后才能宣称多节点生产可用。

### R4 Skill 加工与治理
- 原始包保留版本、脚本、资源及来源，不进入默认自动发现；显式调用仍可用。
- 全文理解后生成运行版。重复流程实质去重，必要差异保留互斥分支或兼容补充模块。
- 浅目录 + 搜索共用能力记录；加载完整必要约束而非只执行检索片段。
- 候选、验证、发布分开；来源与权限冲突不自动合并；发布版本固定到任务。
- 验收：原始条目不泄漏、硬条件过滤、分支绑定准确、来源可追溯、旧任务不被更新中途替换。

### R5 岗位授权与 MCP 懒加载
- 岗位限定 MCP、工具操作、账户、资源与数据出站范围。
- 每个开放 MCP 有已发布 Skill 入口覆盖；不强制一对一。
- Skill 激活解析结构化依赖，只加载该分支/阶段所需工具。
- 发现不授予权限，实际调用再次鉴权；缺必需工具时失败，不能静默少执行步骤。
- 验收：隐藏工具直接按名调用仍拒绝；不存在的/变更的接口拒绝；加载不自动产生业务副作用。

### R6 多层记忆与 PostgreSQL
- 分开管理用途、访问范围、L0/L1/L2 读取深度。
- 必要工作状态自动恢复；长期经验按事件检索；自动增量记录与提炼分开。
- 来源、版本、有效期、确认状态、撤回与审计不可缺失。
- 外接 PostgreSQL 是多节点权威存储；正文、证据与版本不只保存为向量。
- 请求 ID 幂等、版本冲突、写入回执；摘要/向量是可重建派生物。
- 撤回不等于物理擦除；检索结果不作为新证据；旧采集任务不能恢复已撤回内容。
- 自动读取、自动采集、手动工具和整理任务分别可控；模型切换不改变记忆所有权。
- 验收：跨项目/岗位隔离、并发冲突、撤回抑制、读后写一致性、数据库失败不虚报已保存。

### R7 搜索
- 复用 Pi 的本地文件搜索；新增独立联网搜索适配，不绑定当前推理模型。
- 搜索和网页提取分开；保留来源、访问时间与截断标识，禁止伪造结果。
- 默认不自动外发项目正文、私密资料或凭据；需要显式配置搜索后端。
- 验收：无密钥/后端失败时报告不可用；取消、结果大小限制、来源格式测试。

### R8 /goal
- /goal 创建/查看目标，支持暂停、恢复、修改与清除。
- 目标包含验收条件、进度和证据；自动续跑有明确次数/预算上限，暂停与取消优先。
- 接入统一调度，不再另建不受计量的“自动继续”循环。
- 普通 Pi 扩展不宣称关闭宿主后仍运行；常驻服务是独立部署组件。
- 验收：跨会话恢复、无限空转保护、重复完成事件、暂停期间不派发、未验收不宣称完成。

## 3. 架构

以可单独测试的 TypeScript 核心加 Pi 扩展适配层开始，避免无必要的 Pi 核心侵入和新依赖。

- Policy：纯函数/状态机，处理模型选择、故障和回切、岗位及能力过滤。
- Execution：任务图、就绪任务、尝试身份、租约、操作回执。
- Capability：原始/运行 Skill 记录、阶段工具绑定、服务侧鉴权。
- Memory：统一存储契约、PostgreSQL 适配、来源与版本、上下文预算。
- Host：Pi 生命周期、/goal、搜索工具、状态展示与错误报告。

只有一个任务控制权、一个预算权威、一个记忆提交协议。模型建议不直接修改权限或验收状态。

## 4. 开发顺序

1. 提交本计划，锁定基线；读取现有扩展与类型接口。
2. 建立无外部服务依赖的策略与调度核心，补充确定性测试。
3. 实现可用的 /goal 与搜索扩展入口，加入状态持久化和宿主生命周期防护。
4. 加入岗位/Skill/MCP 绑定与多层记忆协议；实现 PostgreSQL 适配及测试边界。
5. 对接真实 Agent 执行器、模型适配、MCP 传输、数据库与隔离运行环境。
6. 故障注入、并发恢复、跨节点与真实模型任务评测；通过之后才扩大使用范围。

本次会尽可能完成可运行实现；未完成或未能连接真实服务验证的内容必须单列，不能用接口、模拟器或文档冒充已完成集成。

## 5. 测试与环境

- 遵循根 AGENTS.md：不用 any/enum/参数属性/动态 import；新测试必须实际执行。
- 修改代码后运行 `npm run check`；依赖安装只用 `--ignore-scripts`。
- 不运行会隐式调用真实服务的整个测试集，不使用真实密钥或付费 Token。
- 新核心测试使用 Node 自带测试运行器与确定性的假时钟/适配器；集成测试分别标明真实或模拟。
- 本会话容器目前无法直接解析 GitHub 域名，远程电脑连接未就绪。通过已授权 GitHub API 开发分支；本地可用 Node 22.16.0 与 TypeScript 5.8.3，低于仓库声明的 Node >=22.19.0。
- 无法执行的全仓检查、真实数据库/MCP/模型调用与跨节点测试必须在交付报告里保留阻断原因，不能写“全部通过”。
