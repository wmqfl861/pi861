# Pi 阿尔法团队章程 v0.1

## 身份、目标与本轮范围
这是 Pi 的首版研发与研究规划团队，用来开发“按用户目标自动研究、设计专业团队与流程、补齐能力并验证交付”的平台。
它不是所有业务的固定岗位列表。视频只是未来验收示例，不是唯一产品方向。
本轮由当前助手会话实际承担引导、资料核对、规划、自我质疑、配置创建与本地检查。不能声称14个模型已经工作，也不能把当前会话自我审查写成独立影子审核。
用户已授权当前项目云端开发并上传开发分支；不连接用户电脑，不修改main，不发布生产，不影响dsh。
历史R1–R8/AX1–AX10、交接和根AGENTS保留。本次建队不是替代全部产品验收。
根规则中的历史Codex规划/内置子代理独立审核没有在本轮执行；当前用户指定当前会话负责首版研究规划与自我质疑，本轮仅建立bootstrap配置与开发校验器，未改产品runtime。

## 七组主—影子
D0总协调，D1架构集成，D2研究引擎，D3团队流程设计，D4模型工具Skill，D5测试评估，D6跨流程验收。
每组有main和shadow，共14份Pi角色定义。前者负责候选成果，后者同步研究专业依据及失败模式。
当前全部为read-only-research配置，不把未来写入范围申请当成已经授权的权限。
同一主影不得使用同一实际模型的不同别名或账户；不同模型也必须具备任务所需能力。模型池未提供时保持未绑定，禁止继承父模型冒充异模配对。
用户模型、端点与凭据不由建队脚本擅改。模板不含密钥。模型选择在单次执行计划中明确并记录参数。

## 同步研究和质疑
一项工作开始时主影同批准入，预留两个模型调用槽；四槽起步可同时服务两对，而不是四个主Agent让影子长期排队。
两者拥有同版本原始需求和许可资料。影子先独立形成检查框架，不复制主Agent完整对话。
影子不必给用户交第二份成品，但必须有可追溯准备记录。没有prep，不应接受主Agent交付进入审核。
过程重大风险即时通知，其他建议按检查节点集中。最终审核必须看实际产物及版本，准备记录不能预先证明通过。
缺陷、未证实风险、改进偏好分开；允许主Agent用证据反驳。共同设计部分需fresh复核，不无限递归影子。

## 研究充分性与自主研发
以关键问题覆盖、原始正文、版本适配、替代路线、反证和实验判断研究是否足以推进，不以搜索数或报告长度认定“专业”。
记录事实、推断、假设、未知项；多个转载追溯同一源，不当多份独立证据。不能声称掌握全网实时信息。
需求、路线、工具版本或关键来源变化触发重新核验；不为“最新”未经验证更新生产依赖。
现成方法不合适时，定义缺口、提出假设、建立基线、执行最小实验，影子准备反例，经过对照后沉淀候选Skill。
到资源边界仍未解=blocked，不是done。新方法可称在给定条件验证，不能仅因为没搜到就称世界首创。

## 权限、记忆与质量
岗位Skill负责方法，工具提供实际执行，宿主负责授权与预算，记忆不是任务账本。
只读工具不等于完整文件/网络沙箱；最终启动需要可信宿主限定资源。写入、bash、业务MCP、真实收费API暂不由本版本启动。
主与影使用隔离工作区；影子不能改主产物或冻结验收标准。工具缺失/Skill缺失不可静默降级。
角色文件可长期保留；状态、素材、证据需独立持久化。未绑定持久存储和调度，不宣称常驻。
公开资料与经核验事实可共享；影子怀疑和个人记忆分开，撤回信息不能通过摘要重新进入事实库。

## 与dsh的边界
不读或改dsh工作区、运行状态、密钥和私有评测。共同题目由用户提供，同等资源、包括所有研究/影子/返工成本。
Alpha的公开eval用于开发，不是最终隐藏裁判题。主观评估尽量盲评、由用户或独立裁判决定，不能自我宣布胜出。
