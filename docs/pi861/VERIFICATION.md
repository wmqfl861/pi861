## 3. 已经接到 Pi 的功能

### Goal

`/goal` 创建目标，支持 status/pause/resume/edit/budget/accept/clear。
扩展派发前保存状态并消费次数，默认最多 20 次。模型提交结果先进入 review，
人工 `/goal accept` 才能确认完成。暂停、用户新输入、取消与恢复不会自动重放旧请求。
次数预算不能等同于总 Token 预算；内部工具循环/原生重试仍需要后续统一计量。

### 搜索

新增可选的 Brave 搜索，默认关闭；独立于当前推理模型。
有固定供应商地址、取消/超时、输出大小限制、来源/访问时间及截断标识。
未完成其他供应商和网页全文提取，未做真实密钥联网验证。

### 基础多层记忆

用户输入自动记录为候选，模型笔记不能自己提升成确认事实或政策。
提供关键词召回、明确来源、版本、撤回和 UTF-8 字节预算的 L0/L1/L2 读取。
默认在原生会话分支保存本地快照，支持恢复同一会话；新会话/多节点共享必须配置外部 backend。
PostgreSQL backend 已有实际 SQL 和组合入口；生产认证/凭据委派服务尚未实现。
摘要目前是注明截取的摘要视图，不是自动生成的语义摘要。

## 5. 已验证的关键反例

- A 经验证完成后，C（依赖 A）能在无关慢任务 B 结束前开始。
- 任务只提交产物但未验收时，不解锁需要验收的依赖。
- 旧节点租约失效后，迟到结果不能提交；结果未知且未声明 retry-safe 的工作不自动重放。
- 故障接管与自动回切四种开关组合；任务改变首选配置后，旧探测不能切回旧模型。
- 用户取消、配置/上下文错误和迟到生成不会盲目触发新业务执行。
- Skill 原始内容不出现在运行目录；工具授权在调用时再次检查，schema 改变必须重新激活。
- 记忆撤回阻止同文本或同旧来源重新写入；重复读写回执不产生新版本。
- 真实 PostgreSQL 上两个相同旧 revision 的并发写入最多一个成功。
- 真实 PostgreSQL 上缺少 scope 的受限连接查不到受保护记录。
- Pi 分支导航不继续使用被放弃分支的本地记忆；旧会话的迟到召回不注入新会话。

## 6. 安全与生产限制

- 路径写入预约只是协调规则，不是 OS 沙箱。
- 内存/单写者 TaskBoard 不是跨进程一致性协议，不允许多个节点直接共享其快照文件。
- 故障重试封装只适用于无副作用的缓冲推理，不能包住工具执行后盲目重跑。
- RLS 使用可信服务设置的事务上下文，不能将数据库凭据给不可信 Agent。
- 敏感信息过滤是启发式，不保证识别所有秘密；回忆不是授权或高优先级指令。
- 撤回不保证物理擦除；原始会话、历史版本及备份可能保留。
- 无真实模型质量评估、节点容灾测试、安全审计或节省费用的实测数据。
- 本批未引入/复制 OpenViking、gbrain 或社区编排插件源码；后续复用需单独核验许可。

## 7. 下一阶段的实施顺序

先接真实 Pi Worker 与统一任务调度，让 /goal 的任务真正分派到隔离执行器；
再接模型请求策略和故障服务，补齐全局预算与操作回执；
随后完成 Skill/MCP 激活及 PostgreSQL 自动提炼/索引消费者。
每条路径先做无付费故障注入，再在明确配置的测试模型、MCP 和隔离环境中验收。
不得用随机睡眠、固定回答或模拟器结果冒充真实多模型/多节点完成。
